# 安全开发流程

## 变更前

1. 标明信任边界、资产、攻击者能力、权限和资源预算。
2. 对照 STRIDE 更新威胁模型；涉及 Secret、签名、部署、设备控制或生产数据时提升为高风险评审。
3. 外部输入契约先定义长度、范围、版本、未知字段和拒绝行为，再实现解析器。
4. 新依赖记录用途、许可证、维护/供应链风险、替代方案和锁定方式。

## 实现与验证

- 默认最小权限、拒绝未知 major/能力、限制集合和消息大小，错误不得泄露 Secret。
- 周期控制路径禁止网络、文件、数据库、阻塞日志、运行期插件发现和无界分配。
- 测试必须覆盖畸形/截断输入、边界值、重放、资源耗尽、失效关闭和恢复路径。
- CI 执行格式/lint/测试、依赖 advisory、许可证/来源策略、NuGet 漏洞与 Secret 扫描。
- 供应链证据必须引用锁文件和提交摘要；Builder、Verifier、Approver、Signer 分离。

## 漏洞响应

发现凭据泄漏时先撤销/轮换再清理历史；发现高危依赖或可利用缺陷时阻止合并与发布。修复 PR 必须包含影响范围、利用前提、回归测试、兼容影响和回滚办法。安全事件的敏感细节不得进入公开日志或普通 Issue。

## 例外

门禁例外必须书面说明范围、风险、补偿控制、负责人和到期时间，并由代码所有者批准。例外到期自动失效，不能永久关闭扫描规则。
